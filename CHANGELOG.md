# Changelog

All notable changes to this project are documented here.

## [Unreleased]

- **Two lines that could cut without the correction, or cut what was not asked (fixes):** a dwell and a move on the same line (`G4 P1 G1 X50`) was passed on as it was, so that move ran with no correction of Z; it is now refused with the number of the line. After `G80` the modal move is cancelled, so axis words alone are refused instead of being written as a cutting move. Two new tests.
- **Behaviour tests at the exact edge:** `tests/behaviour.rs` adds 18 deterministic tests without changing the behaviour: the words of a line (comments, checksum, signs and points, the line named in each error), the way a coordinate is written (a value that rounds to zero has no sign, read back within half a decimal), the correction of the axis A, the range of each setting with both ends, and the surface between the measured points (the bicubic surface goes through every measured point of seeded maps, a plane is reproduced exactly inside the grid, the nearest edge outside it, the doubtful readings with a strict limit and the distance from the plane).
- The shared workflow checker (`tools/workflow_hygiene.py`) is the current one of the documentation hub: the filters under a trigger (branches, paths, types) are no longer read as events.

## [0.1.2] - Arcs cut into pieces that follow the table, the program levelled line by line through a safe emitter and the start position taken from a report of the machine

- **The pictures of the README are new:** they were written again by the picture mode (`--shot`) of the published program.
- **Requirements with identifiers and tests that name them:** `docs/REQUIREMENTS.md` is the register of what the program must do, one row for each capability with an identifier (`ALVL-001` on), its state (planned, prototype, implemented or validated), how far it is (done, partial, pending or blocked), its evidence and the test that shows it; a capability that is not written names the test that will show it. `tests/reqs.rs` reads the table and fails when a test does not exist, when a state does not agree with the progress or the evidence, when `docs/STATUS.md` does not say the same numbers, when a README does not link the documents or when a document holds a date or a private reference. The five documents of the family (`docs/SCOPE.md`, `docs/REQUIREMENTS.md`, `docs/STATUS.md`, `docs/NOT_YET.md` and `AGENTS.md`) are in the repository and are linked from the eight READMEs.
- **Arcs can be cut into pieces:** with `arcs = cut` in the settings file (or `--arcs cut`) an arc (G2 or G3 in the plane of X and Y, with the offsets I and J, with the radius R, or as a full circle) is cut into straight pieces whose ends lie on the circle; `arc-tolerance-mm` (0.001 to 1 mm, 0.01 by default, or `--arc-tolerance`) is the most that a piece may stray from the arc, a piece is never longer than the segment either, each piece gets the Z that the map gives for its end, and the Z of the arc goes in a straight line from where it was to where it ends (a helix). The arc is modal like the other moves and G90.1 gives the centre as a place. An arc with no centre, a radius that is 0 or too small, an end that is not on the circle, R together with I or J, or the word P is refused with the number of the line. It is off by default: arcs are refused with their line as before. `apply` tells how many arcs were cut.
- **A stream that levels the program while it is sent:** `eh3d-autolevel stream MAP.txt IN.nc` runs the program through an emitter that levels it line by line, with the same result as `apply`, into a simulated machine. It stops in a safe state (the spindle off and the tool lifted, nothing more sent, not even the line that broke the rule) and exits with the code 2 when a line goes outside the measured area by more than `stream-outside-mm`, would take the tool below `stream-min-z-mm`, gets a correction of Z beyond `stream-max-shift-mm` or cannot be levelled (an arc while arcs are refused, a code that moves the origin, a program that is levelled already). `--out FILE` keeps the lines that were sent and `--json` prints the result as one object. The library has the emitter (`stream::Streamer`) and the simulated machine (`stream::SimMachine`); the sending program of the suite does not call it yet, and nothing is sent to a real machine.
- **The start position can be read from a machine:** `--start X,Y,Z`, or `--start-report FILE` with a saved status report of GRBL or the answer to `M114` of Marlin, says where the tool stands when the program starts, instead of assuming 0 on every axis (`apply` and `stream`). The reports are read with the readers of the controller crate of EH3D-COMMON, and the Z that a machine reports, which already carries the correction of the table, is turned back into the Z of the program. A machine that is moving, in alarm or silent, a report with only the position of the machine and no work offset, and a place that is not a number are refused with the reason; the tests use the simulated GRBL of the suite, also through a cable that cuts the answers and adds noise, and damaged reports never panic.
- **New settings:** `arcs`, `arc-tolerance-mm`, `stream-min-z-mm` (-10 by default), `stream-max-shift-mm` (2 by default, 0 for no limit), `stream-outside-mm` (0 by default) and `stream-safe-z-mm` (5 by default), each with its range and the line of its error; `examples/autolevel.cfg` is still the file that `eh3d-autolevel config` prints.
- **The register of requirements has 17 new rows:** the cutting of arcs and its checks, the stream and its limits, and the start position are in `docs/REQUIREMENTS.md` with a test each; `docs/STATUS.md`, `docs/SCOPE.md`, `docs/NOT_YET.md` and the eight READMEs say the same, with 267 tests.
- **The CI and the release build take `EH3D-COMMON` at `v0.3.0`:** the sibling that is checked out has the controller crate with the simulated machines, which the program now uses; the manifest asks for `min_common` 0.3.0.

## [0.1.1] - Send levelled programs and maps to the EH3D server

- **A server mode over the client of the suite:** the settings file takes the keys `server_address`, `server_token`, `server_machine`, `server_timeout_s` (1 to 120, 15 by default), `server_retries` (0 to 5, 2 by default), `server_mdns` (`off` by default) and `server_max_answer_mib` (1 to 256, 8 by default), read with their ranges by `eh3d-serverclient` of EH3D-COMMON; a value out of its range, a key given twice or a space in the address is an error that says its line; the mode is off until `server_address` is set and the local work never depends on it.
- **`eh3d-autolevel server status`:** shows the link (the token as `***`) and what the server answers at `/health`, with the refusals and the failures of the network told by their code in the language of the system (taken from `LC_ALL`, `LC_MESSAGES` or `LANG`).
- **`apply --to-server` keeps the corrected program on the server:** the G-code that `apply` writes is kept on the EH3D server as an artifact once it is written locally (one request, never repeated by the client), with the map, the program, the method, the moves, the pieces added, the shift of Z and the decimals as its parameters; the option is refused before any work when `--config` has no `server_address` or `server_token`, and with `--dry-run`, which writes nothing; a refusal of the server is told after the local file was written.
- **`info --json --to-server` keeps the JSON of the map:** the object that `info --json` prints is kept as the artifact `MAP.info.json`; `--to-server` is refused on `info` without `--json`.
- **`demo-map --to-server` keeps the map it writes:** the simulated map is kept as plain text next to the local file, so a program that reads a height map (ISOCAM does) can take it from the server.
- **The CI and the release build take `EH3D-COMMON` at `v0.2.5`:** the sibling that is checked out is the release that has the client of the server, and the manifest asks for `min_common` 0.2.5.

## [0.1.0] - Doubtful readings of the map, extra information and noisy demo maps

- **A point of the map that reads far from its neighbours is shown as a doubtful reading:** `apply` (on the error output, before it writes the program, which it writes all the same) and `info` list a point that reads more than `--spike MM` (or `spike-mm` in the settings file, from 0 to 10 mm, 0.1 by default, 0 for no check) above or below what its neighbours give: along each axis with both neighbours measured, the mean of the pair, then the mean of the axes, which is exact for any plane. A probe that slipped or a chip under the tip is the likely cause. Only the point that is furthest off of the ones around it is listed, a corner is never judged and a point whose neighbours were not measured is skipped.
- **`info` tells more about the map:** the grid (columns, rows, area and spacing), the roughness (the root mean square distance of the measured points from the closest plane, 0 for a plane) and the numbers of the points that were not measured (the first ten, with how many there are).
- **`--json` for `info` and `apply`:** one JSON object instead of the sentence, for other programs to read: the grid, the spread, the tilt, the roughness, the points not measured and the doubtful readings for `info`, and what the correction did (moves, pieces, the range of the shift, the rotary and outside counts, whether it was a dry run) with the number of doubtful readings for `apply`; a number that is not finite is `null`.
- **`demo-map` can make a map with reading errors:** `--noise MM` adds to every point of the simulated table an error of up to MM (0 to 1), `--seed N` makes the same map every time and `--bad COL,ROW,MM` adds MM to one point, so that the check of doubtful readings and the rest of the chain can be tried without a probe.
- **The CI and the release build take the shared libraries at their newest releases:** the pins of the sibling repositories in the workflows are raised to the releases the program now needs, so that the build and the binaries of a release use them.

## [0.0.9] - Refusal of moves that leave out an axis, warnings outside the measured area and a probing simulation

- **A setting to refuse a move that leaves out an axis the program has not set:** `unknown-axis = refuse` in the settings file (or `--unknown-axis refuse`) refuses, with the number of the line, a move that leaves out X, Y or Z before the program has set it; the default `assume-zero` is the way it always was (the program starts at 0 on every axis). Tests cover both, the reading of the setting and its place in the default file; the README says it in the eight languages.
- **The README says the maturity of the manifest:** the badge and the Maturity row of the eight READMEs read functional, as the manifest does, and the check of the status lights now fails when they differ.
- **A program that goes outside the measured area is warned about:** the report counts the corrected points that lie outside the grid (and the largest distance from it) and says how far the reference point is from it; `correct` and its dry run print one warning, because there the height is the one of the nearest edge, which was not measured.
- **The spindle and coolant words of a cut move go with its first piece:** the controller does `M3`, `M4`, `M5` and the coolant words (`M7` to `M9`) of a block before its motion, but they were written on the last piece, so the first pieces cut with the spindle (or the laser) off, or kept it on after a stop. They now go with the first piece, and the words that end or pause the program (`M0`, `M1`, `M2`, `M30`) stay with the last. README and tests follow.

- **Simulation of a probing session:** add `tests/probe_session.rs`, a twin of the probe node that sends the readings of a simulated table (the same seed gives the same readings) and fails once by plan: no contact, a garbled line, the reading of another point, a spike. A session driver stores only the reading of the point it asked for, tries a point again, stops when the map cannot be completed and resumes from a map saved as text after a cut. Seven tests cover the retry, the refusal of half a map, the lines that are not stored, the resumed session that gives the same map, the spike found by its distance from the plane and measured again, and a point that never touches. Nothing has run on a real probe.

- **The shared validation tools are updated:** the validator also runs the workflow and lessons checks of the suite with their latest rules, including a check to run before every push.
- **The CI validation checks the workflows and the lessons of past CI failures against a baseline:** `tools/workflow_hygiene.py` and `tools/lessons_lint.py` (copies of the shared tools) run in the validation, and only findings that are not in `tools/workflow_hygiene_baseline.json` and `tools/lessons_lint_baseline.json` fail it, so what exists today stays as it is and a new one is caught. `python tools/workflow_hygiene.py --root . --detail` and `python tools/lessons_lint.py --repo .` list the findings.
- **The validation of the CI is the reusable one of the documentation hub:** the job `validate` calls `validate.yml` of EH3D-DOCS (pinned by commit) and the check of the CHANGELOG is a job of its own.
- **The pins follow the new releases:** the CI and the release build take `EH3D-COMMON` at `v0.2.1` and `EH3D-CORE-LIBS` at `v0.0.9`, and the manifest asks for `min_common` 0.2.1. The picture of the window in the README is taken again with the program of today.

## [0.0.8] - Rotary axes A, B and C and the same size limit on the command line

- **Fuzz tests with a fixed seed:** 800 random programs (with the compensation of A and B on) are levelled or refused without a panic and without a number that is not finite, the same program gives the same levelling every time, and a program cut at any byte is levelled or refused.

- **The axes B and C complete the rotary axes:** the axis B has the same compensation of Z as A with its own radius (`b-axis-compensation`, `b-axis-radius-mm`, `--b-compensation`, `--b-radius`; the two add up and the notice names B), and C, which turns about Z, changes no height and is carried and interpolated like the others. `tests/rotary_axes.rs` walks the levelled program with a simulated machine and checks the depth below the table with A, B and C turning inside moves cut in pieces; nothing has run on a machine with rotary axes.

- A screenshot of the window in the README, taken with the published program: an example program over the height map of an example table.
- **The command line reads files with the same size limit as the window:** the height map, the settings file and the G-code program given to `apply`, `info` and the other commands are refused with their name when they are larger than 256 MiB, instead of being loaded into memory whole; two more tests (174).
- **Z correction for the turn of the axis A:** `a-axis-compensation = tilt` and `a-axis-radius-mm = r` in the settings file (or `--a-compensation tilt --a-radius r`, which win over the file) add `r * (1 - cos A)` to the Z of every written move after the height of the table, with A in degrees as the move leaves it (interpolated piece by piece, modal like the other axes). It is `off` by default, which changes no output; `tilt` with a radius of 0, or a radius beyond -1000 to 1000 mm, is an error that says its line (file) or names the option. `apply`, and `apply --dry-run`, show a notice on the error output with the number of moves and the largest correction when it was applied, and the shift is part of the `Z shifted from ... to ...` summary and of `warn-shift-mm`. The formula and worked values are in `docs/a-axis-compensation.md`; `examples/autolevel.cfg` carries the new keys and is the same file as `eh3d-autolevel config`.

## [0.0.7] - Rotary axes kept between moves, a warning when the correction of Z passes a limit and the picture mode

- **A warning when the correction of Z is large:** `warn-shift-mm` in the settings file (or `--warn-shift MM`, which wins over the file; 0 by default: no warning, otherwise from 0.001 to 100 mm) makes `apply`, and `apply --dry-run`, show on the error output the largest correction of Z, with its sign, when it passes the limit up or down; the corrected program is written all the same and the exit code does not change. `examples/autolevel.cfg` carries the new key and is the same file as `eh3d-autolevel config`. The tests use a table that rises 0.001 mm for every mm (0.05 mm at X = 50) and the range of the setting.
- **The rotary axes A, B and C are interpolated:** when a cutting move (G1) is cut in pieces, its `A`, `B` and `C` words go in a straight line from the value they had to the one the move gives, like X and Y, written with the configured decimals; the last piece ends exactly on the target and the Z of the table still comes from X and Y only. The axes are modal (a move with no `A` writes none, a line with only rotary words or a rapid move sets where they stand) and start at 0. A move that is not cut keeps its words as they were written, and a program with no A, B or C is written exactly as before.
- **`max-lines` in the settings file:** the most lines the levelled program may have (5000000 by default, from 1 to 100000000), a new strict key with the error of its line (not known, not valid, given twice); `--max-lines` on the command line wins over the file and `eh3d-autolevel config` prints it with the rest.
- **A picture mode for the window:** `--shot FILE.png` (built with `--features gui`) opens the window at the size of `--size WxH` (320 to 8192, 1180x760 by default), with `--theme forge|dark|light`, `--lang CODE` and the files of `--open FILE`, waits `--wait N` frames (0 to 3600, 6 by default), saves what it drew as a PNG file and closes by itself. An existing file is never replaced unless `--replace` is given, the window keeps no settings in this mode, the exit code is 0 when the file was written, 1 when it was not (also when the picture does not come back within 600 frames) and 2 for wrong arguments, and a build without the window says so. The arguments are read by plain code with its tests.

## [0.0.6] - The window with the height map, the standard header of the levelled program and the Windows icon

- **The coordinates of the levelled program have three decimals:** X, Y and Z are always written with the same number of decimals (`G1 X1.000 Y0.000 Z-0.100`) instead of as many as were needed up to four; the other words (`F`, `S`, `M`...) are written as before.
- **A settings file with the decimals:** `decimals` (3 by default, from 1 to 6) is read from a `key = value` file given with `--config FILE` or given on the command line with `--decimals N`, which wins over the file; `eh3d-autolevel config` prints the file with its defaults (`examples/autolevel.cfg`). A value that is not valid, a key that is not known or a key given twice is an error with the number of the line.
- **Binaries for every system:** `release-binaries.yml` builds the program with its window for Windows (64 and 32 bits), Linux and macOS (Apple silicon and Intel), packs each one with the licence, the readme, the icon and the examples, writes `SHA256SUMS` and a build manifest, attests their provenance, verifies the artifact as a stranger would, prepares a draft release only after the owner approves it (a dry run is the default) and opens an issue `build-failed` when anything does not finish.
- **The dependencies on the shared readers name the version that has what is used:** the G-code crate (and for ISOCAM the Excellon one) is required from 0.0.7, the version that brought the way of writing a number, the header of a program and the units given by the caller.
- **The levelled program starts with the standard header:** the generator and its version, the units, the program it came from with its SHA-256 and the tools, as comment lines before the mark (`mark_with_header`); the mark is found where it is, so a levelled program is still refused the second time.
- **The G-code is read back in the tests:** the levelled program and the file of the command line are read with the reader of the suite and walked the way the strict mode of the G-code debugger walks them; there is no warning, no rapid move into the material and no cut with the spindle off.
- **A window:** built with `--features gui`, `eh3d-autolevel` with no arguments (or with files, or `gui [FILE...]`) opens a window in the look of the other programs of the suite (amber on charcoal, the icon of the program). A G-code program and a height map are opened from the list of files of the window or dropped on it (the first line tells a map from a program); the table is drawn as a coloured mesh, the original path and the levelled path over it (coloured by the table under each piece), with zoom (wheel), pan (drag) and the height of the table under the pointer; the longest piece, the reference point, the surface (bilinear or bicubic) and the most output lines can be edited, a simulated table can be made, and the levelled program (with the mark that says it was levelled) and the map are exported. The command line works as before, and a build without the feature is only a command line.
- **The window speaks the eight languages:** English, Spanish, German, French, Italian, Japanese, Chinese and Portuguese of Portugal, chosen from the system and changeable in the window.
- **The logic of the window needs no screen:** `window` (program, map, settings, levelling, paths, colours, export, status), `viewport` (zoom and pan), `browse` (the list of files) and `lang` (the words) are plain code with their own tests; `gui` only draws them. `gcode::words` is public for the picture of the paths.
- **The Rust version needed is 1.88,** the one the window needs.
- **Lines that are not moves pass through:** `$` commands, `#` assignments and the messages `M117` and `M118` are written as they are, and the checksum of a numbered line is not read as a word.
- **The M words of a cut move go with its last piece:** `G1 X50 M5` stops the spindle at the end of the move and not at its first piece.
- **The size of the output is limited:** `--max-lines` (5000000 by default) refuses a program that would have more lines, before the pieces are made.

## [0.0.4] - CI hardening and shared validator

## [0.0.3] - Dry run and shared argument helper
- **The CI builds against the tag of each sibling:** the sibling repositories are read from `depends_on` of the manifest (the ones they need in turn included) and checked out at the tag the repository is built from, so a build does not move when a sibling changes; a separate job, `Siblings at main`, builds against the main branch of every sibling to show a break before the sibling is tagged and does not hold a merge.

## [0.0.2] - A program is never levelled twice, a strict command line and the versions of the sibling repositories

- **Each dependency on a sibling repository by path says the version it needs** (`version = ">=0.0.1", path = "../EH3D-..."`), so Cargo stops at once when the sibling next to this one is older than the program expects.
- **Never levelled twice:** the corrected program starts with a comment line that says it was levelled and with which map; a program that carries it is refused with its line, because the correction of the table would be added twice.
- **Strict command line:** an option that is written wrong (`--powr`) or a word too many is an error that names it; before, it was ignored and the output was made with the default values.
- **Codes that change the origin or the offsets are refused:** G10, G28, G30, G38, G43, G53, G92 and any other G code that is not a plain move or a setting that leaves the position alone stop the program with the number of the line, instead of being turned into a move to Z0. A dwell (G4) is kept as it is, the `%` line of the start and the end of a program passes through, and a map that gives no finite height is refused instead of writing `Z NaN`.

## [0.0.1] - A G-code program corrected with the height map of the table, bilinear or bicubic

- **The program:** cutting moves are cut in pieces that follow the surface; rapid moves are corrected only when they have a Z; the reference point is the zero of the correction.
- **The surface:** bicubic (Catmull-Rom) next to the bilinear one of the map, with the nearest edge used outside the grid.
- **What is refused with its line:** G91, G20, arcs, a move before G0 or G1, bad numbers, huge coordinates, too many pieces and a map that is not complete.
- **The command line** `eh3d-autolevel` with `apply`, `info` and `demo-map`, and an example table and program.
- **13 tests** run on a computer, with damaged input.
